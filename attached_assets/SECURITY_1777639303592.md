# Bug Bounty Pro - Security & Architecture Documentation

## Executive Summary

**Bug Bounty Pro** is an enterprise-grade, authorized security assessment platform built for comprehensive web application vulnerability detection. It combines automated discovery, safe validation checks, AI-powered analysis, and manual workflow support to identify security issues in a non-destructive, auditable manner.

### Key Characteristics
- **Authorization-First**: Explicit authorization acknowledgment required before any scan
- **Non-Destructive**: All validation modules use safe, read-only probes
- **Comprehensive**: 10 phases of security testing from discovery to reporting
- **Auditable**: Complete audit trail of all activities and findings
- **Scalable**: Distributed architecture with Redis queuing and worker processes
- **Professional**: Enterprise-grade reporting in multiple formats (HTML, PDF, SARIF)

## Security Features

### 1. Authentication & Authorization

#### GitHub OAuth + JWT

```
User → GitHub → OAuth Token → JWT Session
         ↓
    Personal Allowlist
    (ALLOWED_GITHUB_USER)
         ↓
    Authorization Check
    (enforce_personal_allowlist)
         ↓
    Scan Access Granted
```

**Key Features:**
- GitHub OAuth integration for identity verification
- JWT token-based session management (3600s default expiry)
- Personal allowlist enforcement (single-user mode)
- Bearer token authentication on all protected endpoints

**Code:**
```python
# app/core/auth.py
def enforce_personal_allowlist(github_login: str) -> None:
    expected = settings.allowed_github_user.strip().lower()
    incoming = github_login.strip().lower()
    if incoming != expected:
        raise HTTPException(status_code=403, detail="Access denied")

def create_access_token(github_login: str) -> str:
    to_encode = {"sub": github_login, "role": "admin"}
    expire = datetime.utcnow() + timedelta(seconds=settings.jwt_expiration_seconds)
    encoded = jwt.encode(to_encode, settings.jwt_secret_key, algorithm=settings.jwt_algorithm)
    return encoded
```

### 2. Authorization Requirements

**Explicit Authorization Enforcement:**

Every scan requires explicit authorization acknowledgment:

```json
{
  "authorization_acknowledged": true,  // Must be true
  "authorization_note": "Authorized by target owner on 2024-04-30"
}
```

**Safety Validation:**
- Checked before job creation
- Enforced by `SafetyValidationError` exceptions
- Prevents accidental unauthorized scanning

### 3. Non-Destructive Operations

**Safe Validation Principles:**

✅ **Allowed (Safe Probes):**
- Marker injection for XSS detection
- Parameter tampering with different values
- Boolean operators in SQL queries
- Response comparison and diffing
- Request/response logging

❌ **Prohibited (Never Used):**
- DELETE/DROP/TRUNCATE statements
- Data modification or deletion
- File system access
- System command execution
- Outbound connections
- Long-running operations that exhaust resources

**Validation in Code:**
```python
# app/services/safety_validation.py
def validate_non_destructive_defaults(job_payload):
    destructive_flags = [
        "drop_database",
        "delete_data",
        "modify_data",
        "destructive_mode",
        "production_unsafe",
    ]
    for flag in destructive_flags:
        if job_payload.get(flag):
            raise SafetyValidationError(f"Destructive flag '{flag}' is not allowed")
```

## Data Security

### 1. Sensitive Data Protection

**Encrypted Storage:**
- JWT secrets stored in environment variables
- API keys never logged or displayed
- Evidence encrypted at rest (if MinIO enabled)

**In Transit:**
- HTTPS-only in production
- TLS 1.2+ required
- Certificate pinning recommended

### 2. Database Security

**MongoDB:**
- Authentication required
- Per-user access controls
- Indexed for performance
- Backups stored separately

**Redis:**
- AUTH required if exposed
- Per-database logical isolation
- No sensitive data stored in cache

### 3. Evidence Management

**Finding Evidence:**
- HTTP snapshots stored with findings
- Screenshots captured safely via Playwright
- Marker strings unique per job
- Evidence preserved across manual review

## Security Testing Modules

### Phase 2: XSS Validation
- **Safe Marker Injection**: Uses unique identifiers per job
- **Reflection Detection**: Compares response for unencoded markers
- **Browser Verification**: Playwright confirmation (safe mode only)
- **Screenshot Evidence**: Visual proof of execution

### Phase 3: IDOR Testing
- **Response Diffing**: Compares legitimate vs. unauthorized access
- **No Data Destruction**: Only reads, never modifies
- **Context-Aware**: Tests with different authentication contexts
- **Confidence Scoring**: Meaningful response differences required

### Phase 4: SQLi Triage
- **Non-Destructive Probes**: Only SELECT-equivalent operations
- **Error Analysis**: Database error signatures
- **Response Variance**: Length and content comparison
- **Safe Timing**: No actual time-based exploitation

### Phase 5: Discovery
- **Bounded Fuzzing**: Configurable probe budget
- **Wordlist-Based**: Uses common path patterns
- **Non-Destructive**: Only probes, never creates/modifies
- **Normalized Results**: Deduplicates similar endpoints

### Phase 6: Authentication Testing
- **JWT Validation**: Token parsing and expiration checks
- **Session Replay**: Reuse of auth headers/cookies
- **Role Differential**: Compares access across privilege levels
- **Controlled Comparison**: No actual exploitation

### Scan Lifecycle

```
1. USER CREATES SCAN
   └─ Provides target URL, auth, authorization
   └─ Validates input (Pydantic schema)
   └─ Checks authorization acknowledgment
   └─ Safety validation checks
   └─ Rate limiting check
   └─ Creates job in MongoDB
   └─ Emits "job_created" event
   
2. JOB QUEUED FOR PROCESSING
   └─ Added to Redis queue
   └─ Status: "queued"
   
3. WORKER PICKS UP JOB
   └─ Dequeues from Redis
   └─ Status: "running"
   
4. PIPELINE EXECUTION
   ├─ Recon Phase
   │  └─ DNS resolution
   │  └─ robots.txt / sitemap discovery
   │  └─ security.txt checks
   │  
   ├─ Crawl Phase

   │  └─ Endpoint normalization
   │  
   ├─ Validation Modules (if enabled)
   │  ├─ Phase 2: XSS Validation
   │  ├─ Phase 3: IDOR Testing
   │  ├─ Phase 4: SQLi Triage
   │  ├─ Phase 5: Auth Testing
   │  └─ Phase 6: Fuzzing
   │  
   ├─ Manual Review Phase (if enabled)
   │  └─ Status: "manual_review_pending"
```

## Security Best Practices

### For Administrators

1. **Keep Secrets Safe**
   ```bash
   # Store in environment variables
   export SECRET_KEY=$(python -c 'import secrets; print(secrets.token_urlsafe(32))')
   export GITHUB_CLIENT_SECRET=$(grep GITHUB_CLIENT_SECRET .env.secure)
   ```

2. **Enable HTTPS in Production**
   ```bash
   # Use Let's Encrypt
   certbot certonly --standalone -d yourdomain.com
   # Configure nginx with SSL certificates
   ```

3. **Rotate Secrets Regularly**
   - JWT secrets annually
   - API keys quarterly
   - Database passwords monthly

4. **Monitor Audit Logs**
   - Review authorization failures
   - Track unusual scanning patterns
   - Alert on authorization bypass attempts

### For Users

1. **Before Scanning**
   - ✅ Verify authorization in writing
   - ✅ Confirm target scope
   - ✅ Check company policies
   - ✅ Review scan profile impact

2. **During Scanning**
   - ✅ Monitor real-time activity
   - ✅ Check for unexpected behavior
   - ✅ Watch resource usage
   - ✅ Review manual review findings

3. **After Scanning**
   - ✅ Verify all findings
   - ✅ Export report securely
   - ✅ Share with authorized team
   - ✅ Create remediation plan

### For Developers

1. **Adding Validation Modules**
   - Always use non-destructive probes
   - Test with destructive_flag rejection
   - Add safety checks
   - Document evidence collection

2. **Extending the API**
   - Validate all inputs with Pydantic
   - Enforce authorization checks
   - Add rate limiting
   - Log all actions

3. **Security Testing**
   - Run `pytest tests/test_safety_validation.py`
   - Verify authorization enforcement
   - Test rate limiting
   - Check for information disclosure

```bash
# Check MongoDB indexes
db.findings.createIndex({scan_job_id: 1, severity: 1})
```
